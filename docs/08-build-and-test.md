# 构建与验证

> 工具链固定、入口统一、证据分层；类型检查 ≠ 构建 ≠ mock 预览 ≠ 浏览器验证 ≠ 线上验收，不能互相替代。

## 工具链固定

- Node 版本用 `.nvmrc` + `package.json` 的 `engines` 双重固定（例：`>=22.13.0 <23`）。
- 包管理器版本用 `packageManager` 字段固定（例 `pnpm@9.15.9`），锁文件必须入库，安装一律 `--frozen-lockfile`。
- 独立工具链的子工程（不同 Node 主版本、不同 pnpm）用自己的 manifest 与锁文件，分别安装、分别运行；**不得用一套 Node 跑另一套 ABI 的原生模块**（如原生 SQLite）。
- 本机预览/开发命令与生产配置分离（`pnpm dev:web` 之类可直接起前端，无需生产配置）。

## 命令分层（示例命名）

```text
install     pnpm install --frozen-lockfile
dev         pnpm dev:web / pnpm dev
check       静态检查集合：运行时/站点配置/环境契约/边界/文档索引/文档同步/执行记录/密钥扫描/类型检查
test        单元与集成测试（vitest run）
test:e2e    浏览器端到端（Playwright，起真实 dev server）
build       各服务生产构建
verify      总入口 = check + test + build + 子工程 check + 子工程 generate
```

- **单一验收入口**（`pnpm verify`）顺序编排全部检查，任一步失败必须非零退出。
- `check` 里的每项检查都是独立脚本，可单独跑；只在一个地方实现，其它文档只引用。
- 子工程（独立技术栈）有自己的 `check/generate/verify`，由根入口编排，不能把两套结果混成一份。

## 证据分层（不可替代）

| 证据 | 证明什么 | 不能证明什么 |
|---|---|---|
| 类型检查 | 类型层面自洽 | 行为正确 |
| 单元/集成测试 | 逻辑与边界按断言工作 | 浏览器中的真实交互 |
| 构建成功 | 能打包 | 运行正确 |
| mock / 静态预览 | 界面形状 | 真实后端行为 |
| 真实浏览器验证 | 交互、布局、动画 | 预发布人工试用 |
| 预发布/线上人工验收 | 用户可用 | —（发布放行条件） |

- 未验证的项必须显式写「未验证」，不得写「应该没问题」；未完成的环境验收不得标为 PASS。
- 既有测试失败要定位，**不得通过删除断言、复制处理器、伪造返回值或固定退出码解决**。
- 行为变更要加「能区分修复前后」的回归测试；新增依赖要说明目的、许可、运行环境、体积与维护代价。

## 测试隔离（硬规则）

- 集成测试用真实路由注册（框架的 `buildApp`/`inject` 之类），只把数据库指向内存库。
- 外部 HTTP 与第三方服务（OAuth、发信等）**默认拒绝**，需要响应的用例显式注入模拟；不读 `.env`、不读业务数据库、不发真实邮件/邀请。
- 不能复制 handler 去验证另一份实现。
- 浏览器测试：每次用自己创建的临时 profile，不打开用户已有配置、不清理用户示例数据；只关闭本次创建的进程组，禁止广泛 `pkill`。
- 测试只对确定性种子/夹具运行；解析类逻辑用虚构夹具单测，不读取真实数据。
- 未找到浏览器不能算套件通过。

## 环境与构建契约

- 每个环境一份环境文件（如 `deploy/env/.env.preview`、`.env.production`），入库；**非密值预填、密钥留空**；字段契约由脚本校验（契约外字段拒绝、两环境端口/域名必须不同、公开地址逐字等于环境 origin）。
- 前端站点配置不得包含任何域名（每个环境一个 origin）。
- 镜像按服务分开构建（web/server/forum），构建上下文为仓库根，基础镜像按 digest 固定；镜像仓库按环境分开。
- 发布身份用 build args 注入（版本、提交 SHA），不写进环境文件。

## CI 结构（示例）

| 工作流 | 触发 | 职责 |
|---|---|---|
| `ci` | PR → 长期分支；push 长期分支与 task/dev 分支 | 分支守门（不变量/命名/执行记录/文档同步）→ 核心 check/test/build ∥ 子工程 check/generate ∥ 环境契约 ∥ 镜像构建校验 → 汇总 |
| 发布部署 ×2 | push 对应 tag；手工重跑（选同一 tag） | 规划（tag 格式/分支/版本号）→ 证据核对 → 构建 → 分发 → 部署 → 健康检查 → 记录 deployment |
| 分支卫生 | PR 合并、每周巡检 | 合并后删 `task/**` 远端分支；残留分支只告警 |
| issue 生命周期 | PR 事件、每日巡检、手工 | PR 契约核对；合并后关 issue 并留记录；超期/缺记录巡检 |
| 证书监控 | 每日 | 从公网核对证书链与到期时间 |

- 汇总成一个 **required check**（如 `verify`），任何上游失败即失败；**不得用 `continue-on-error` 掩盖失败**。
- CI 用 `fetch-depth: 0`（浅克隆会让依赖历史时间的检查失去意义，遇到浅克隆应直接报错）。
- 同一 PR/分支推新提交时取消旧运行；push 长期分支不取消。合并进长期分支的提交要等这次 CI 通过后再打 tag。
- 部署工作流：默认开关关闭；同一时刻只跑一个、不取消正在跑的；手工运行必须从同名 tag 运行并填这个 tag。
- `dev/**` 只做机器验证，不部署、没有任何发布含义。

# 文档与模块规范

> 区分当前事实、已接受决策、未实施提议和历史材料；模块与文档严格对齐；同一条规则只在一个地方定义。

## 文档结构

- 所有规范、架构、服务合同、设计决策和运维说明集中在根 `docs/`；根 README/入口文件只作导航，不建立第二份知识库。
- 目录即类别：协作规范（conventions）、服务合同（services）、当前系统（architecture）、交互与选型（design）、运维（ops）、决策（decisions）、计划与历史（plan/history/handovers）、交付证据（reviews）。
- 每篇技术文档至少包含：一级标题、首个引用块摘要、状态、更新日期、适用范围、事实来源或代码位置、约束与验证方法。
- 索引是生成物（脚本生成，不手工维护）；标题、摘要、路径变更后重新生成。

## 状态词表（只有四个）

| 状态 | 含义 |
|---|---|
| `current` | 当前有效 |
| `accepted` | 已接受的决策（不等于代码已落地，正文须列实施状态） |
| `proposed` | 未实施的提议 |
| `historical` | 历史记录 |

- **历史与提议文档不覆盖 current 规范，也不得被当作现行操作依据**；历史材料必须显式标注历史。
- 代码与 current 文档不一致是缺陷，必须在改动中说明并同步修正；不能通过「随意选择某份文档」掩盖冲突。
- 规范冲突时自己挑一份照做而不报告，是禁止事项。

## 文档跟着模块改（硬规则）

模块改了，对应文档要在**同一个 PR** 里跟着改；对照表是唯一清单，检查脚本逐行核对，不通过不能合并。示例对照：

| 模块路径 | 文档路径 | 头部「更新：」看哪份 |
|---|---|---|
| `app/server/` | `docs/services/server/` | 该目录 `README.md` |
| `app/web/` | `docs/services/web/` | 该目录 `README.md` |
| `deploy/` | `docs/ops/DEPLOY.md` 等 | 同左 |
| `.github/workflows/` | `docs/ops/CICD.md` | 同左 |

规则细节：

- 从 merge-base 到现在，动了模块路径就要改对应文档里的说明，**或者**在这个 task 的执行记录里写文档核对。
- 只改「更新：」日期、空白或空行**不算**改了说明（比较时忽略空白和空行）。
- 文档头「更新：」日期不能早于模块最后一次改动的作者日期（用作者时间，避免零点前写、零点后合并被误判）。
- 文档事实确实没变（只改测试、重构、返工）时，在**本 task 的执行记录**里写：
  `文档核对：<文档路径> 不用改——<理由>`
  （路径照抄对照表第二列；理由必须真实，审查人对照 diff 核实；照抄模板占位符或只写标点的理由不算。）
- 要有完整历史：浅克隆直接报错；CI 检出写 `fetch-depth: 0`。
- `app/` 下每个服务目录（含未跟踪的新目录）都必须出现在对照表里，表里写的路径必须存在；不设排除项。
- 文档核对写在执行记录里而不是共享文档里：每个 PR 只改自己的记录文件，不会让并行 PR 互相冲突。

## 模块边界与契约

- **一个服务一份契约**：`app/<service>` ↔ `docs/services/<service>/README.md`（源码地图、公开接口、依赖、数据归属、运行方式、验证命令、已知限制、异常与测试）。
- **新增服务 = 新增 `app/<service>` + 新增 `docs/services/<service>/README.md` + 在地图里加一行**，缺一视为未完成；模块细节放同目录子文档。
- 依赖方向单向、显式：站点 → shared → 通用依赖；启动 → 组装 → 路由模块 → 策略/持久化/适配器。禁止站点互相导入、shared 导入站点、路由模块互相导入、底层导入路由或组装、跨前后端导入对方实现。
- 跨服务只通过显式 URL / HTTP 契约连接，禁止共用可变 store 或直接读对方数据库。
- **契约是输入协议源**（如模块 `contracts.ts`），路由只做 HTTP 映射、授权与调用；多处共用的规则放具名策略/服务，不在每个 handler 复制。
- 引用外部版本/标准时给出官方来源与核对日期；未经核对不写「最新版」；未落地的目标只能写在 `proposed` 或明确标「未做」。

## 发布边界（文档层面）

- 文件在 `docs/` 不代表可以公开：公开 API 用显式白名单，只允许产品介绍和用户指南；运行路径、部署步骤、安全模型、审查报告不自动发布。
- 任何文档不得写真实 Token、密码、会话 cookie 或完整环境文件；部署环境文件只允许写地址、端口、域名等可见事实，密钥字段留空。
- 中文是主要规范源；英文伴随文档是明确标记的导航概要，必须保持同步，不留与实现矛盾的第二份完整指令。

## Agent 入口门禁（通用做法）

- **只有一个 agent 入口文件**（如 `AGENTS.md`），保存硬门禁摘要与导航；细节全在 `docs/`，不在入口复制第二套规则。
- 其他工具适配器（`CLAUDE.md`、`.cursorrules`、copilot instructions 等）要么删除，要么只是指向唯一入口的纯跳转/符号链接；**禁止复制内容形成第二份规则**；技能实现只有一份，其它目录符号链接过去。
- Agent 进入仓库的第一件事：确认当前分支（`git branch --show-current`），然后完整读完必读规范；读完之前禁止编辑文件、装依赖、跑脚本、操作数据、启停服务、任何 Git 写操作。
- 上下文压缩、恢复会话、切换模块后，重新确认并补读；文档被截断就继续读到完整；文件缺失或规范冲突时停下报告阻塞，不凭记忆继续。
- 授权与动作、目标环境、具体提交匹配：「继续」「测试都过了」不等于人工验收通过或发版授权。
